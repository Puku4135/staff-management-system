# 店舗スタッフ管理システム ― 新人教育の進捗を見える化するWebアプリ

飲食店などの店舗において、  
スタッフ情報と新人教育の進捗状況を管理するためのWebアプリケーションです。

スタッフごとに、

- どの教育項目を習得しているか
- 現在どの段階まで進んでいるか
- 誰が教育を担当しているか
- 教育時の備考

を記録し、教育状況を一覧で確認できるようにしています。

職業訓練で学習したJava、Spring Boot、MySQLなどの技術を使用して制作しました。

# 1. 概要

本システムは、店舗で働くスタッフの基本情報と、  
新人教育の進捗状況を管理するWebアプリケーションです。

スタッフごとに登録されている教育項目について、

- 未着手
- 練習中
- 習得済み

の3段階で状態を管理できます。

また、「習得済み」となっている教育項目数から、
スタッフごとの教育進捗率を自動計算し、
スタッフ一覧画面から確認できるようにしています。

---

# 2. 制作背景

飲食店で勤務していた際、新人スタッフの教育を担当した経験があります。

複数のスタッフを教育する中で、

- 誰がどの項目まで習得しているのか
- どの項目がまだ十分にできていないのか
- 誰がそのスタッフの教育を担当したのか
- 前回どのような内容を教えたのか

といった情報を把握する難しさを感じました。

特に、教育担当者が変わった場合には、
スタッフの現在の習得状況を改めて確認する必要があります。

そこで、

**「スタッフごとの教育状況を見える化し、教育担当者が情報を共有しやすくする」**

ことを目的として、本システムを制作しました。

---

# 3. 主な機能

## 3.1 スタッフ管理

スタッフの基本情報を管理します。

- スタッフ一覧表示
- スタッフ新規登録
- スタッフ編集
- スタッフ削除
- スタッフ名検索
- No.順での並び替え
- 入社日の新しい順での並び替え
- 入社日の古い順での並び替え

---

## 3.2 教育項目管理

新人教育で使用する教育項目を管理します。

各教育項目には、

- 教育項目名
- カテゴリ
- 習得目安日数

を登録できます。

主な機能は次のとおりです。

- 教育項目一覧表示
- 教育項目新規登録
- 教育項目編集
- 教育項目削除
- カテゴリによる管理

---

## 3.3 スタッフ別教育状況管理

スタッフごとに各教育項目の進捗状況を管理します。

管理する情報は次のとおりです。

| 項目 | 内容 |
| --- | --- |
| 教育項目 | 教育する内容 |
| カテゴリ | 教育内容の分類 |
| 習得状況 | 未着手 / 練習中 / 習得済み |
| 習得目安 | 習得までの目安日数 |
| 教育担当者 | 教育を担当したスタッフ |
| 備考 | 教育内容や注意点など |

---

## 3.4 教育進捗率

登録されている教育項目数と、
「習得済み」となっている教育項目数から
スタッフごとの進捗率を計算します。

例：

```text
教育項目数：5件
習得済み：3件

3 × 100 ÷ 5
= 60%

進捗率：60%

進捗率はスタッフ一覧画面から確認できます。

```

# 5. システム構成

本システムでは、処理の役割を分かりやすくするため、
Controller・Service・Repositoryを分けて構成しています。

```text
ブラウザ
    ↓
Controller
    ↓
Service
    ↓
Repository
    ↓
MySQL
```

各構成の主な役割は次のとおりです。

| 構成 | 主な役割 |
| --- | --- |
| Controller | URLやフォームから送信されたリクエストを受け取り、画面遷移を制御する |
| Service | 登録・更新・削除・検索・進捗率計算などの処理を行う |
| Repository | MySQLへのデータ保存・取得・削除を行う |
| Model | スタッフ・教育項目・教育状況などのデータを表現する |
| Thymeleaf | Controllerから渡されたデータをHTMLへ表示する |
| MySQL | スタッフや教育状況などのデータを保存する |

役割ごとに処理を分けることで、
「どのクラスが何を担当しているのか」を確認しやすい構成を意識しました。

# 6. データ構成

本システムでは、主に次の3種類のデータを管理しています。

## 6.1 Staff

店舗スタッフの基本情報を管理します。

| 項目 | 内容 |
| --- | --- |
| id | スタッフID |
| name | スタッフ名 |
| joinDate | 入社日 |

---

## 6.2 Skill

新人教育で使用する教育項目を管理します。

| 項目 | 内容 |
| --- | --- |
| id | 教育項目ID |
| name | 教育項目名 |
| category | カテゴリ |
| estimatedDays | 習得目安日数 |

---

## 6.3 TrainingProgress

スタッフごとの教育状況を管理します。

| 項目 | 内容 |
| --- | --- |
| id | 教育状況ID |
| staffId | スタッフID |
| skillId | 教育項目ID |
| status | 習得状況 |
| trainerName | 教育担当者 |
| memo | 備考 |

`staffId` と `skillId` を使用することで、

```text
スタッフ
   +
教育項目
   ↓
教育状況
```

という関係を表現しています。

たとえば、

```text
スタッフ：山田太郎
教育項目：レジ操作
習得状況：練習中
教育担当者：佐藤
備考：基本操作は理解済み
```

といった形で、
スタッフごとの教育状況を管理できます。

# 7. 工夫した点

## 7.1 実際の新人教育経験をもとに制作

本システムは、
過去に飲食店で新人教育を担当した経験をもとに制作しました。

新人スタッフを教育する中で、

- 誰がどの項目まで習得しているのか
- どの項目がまだ練習中なのか
- 誰が教育を担当したのか
- 前回どのような内容を教えたのか

といった情報を把握する難しさを感じました。

そこで、単なるスタッフ情報管理ではなく、

**「新人教育の状況を分かりやすく確認できること」**

を意識して機能を構成しました。

---

## 7.2 教育状況を3段階で管理

各教育項目の状態を、

```text
未着手
   ↓
練習中
   ↓
習得済み
```

の3段階で管理しています。

「できる・できない」だけではなく、
現在練習している途中の状態も管理できるようにしました。

これにより、教育担当者が現在の進捗を把握しやすくしています。

---

## 7.3 スタッフごとの進捗率を自動計算

スタッフごとの教育状況を確認し、
「習得済み」になっている教育項目数から
進捗率を自動で計算しています。

例：

```text
教育項目数：5件
習得済み：3件

3 × 100 ÷ 5
= 60%

進捗率：60%
```

進捗率はスタッフ一覧画面に表示されるため、
各スタッフの教育状況を一覧から確認できます。

---

## 7.4 検索・並び替え機能

スタッフ数が増えた場合でも
目的のスタッフを探しやすくするため、
検索と並び替え機能を実装しました。

スタッフ一覧では、

- スタッフ名検索
- No.順
- 入社日が新しい順
- 入社日が古い順

で表示できます。

また、検索したスタッフ一覧に対しても
並び替えを行えるようにしています。

---

## 7.5 関連データを考慮した削除処理

スタッフや教育項目を削除した場合、
関連する教育状況データだけが
データベースに残らないようにしています。

スタッフ削除の場合は、

```text
スタッフ削除
    ↓
関連する教育状況を削除
    ↓
スタッフ本体を削除
```

教育項目削除の場合も、

```text
教育項目削除
    ↓
関連する教育状況を削除
    ↓
教育項目本体を削除
```

という流れで処理しています。

また、複数のDB操作を1つの処理として扱うため、
削除処理ではトランザクションを使用しています。

---

## 7.6 入力値や想定外の値への対応

正常な画面操作だけでなく、
想定外の値が送信された場合についても
一部確認処理を実装しています。

主な確認内容は次のとおりです。

- スタッフ名の未入力
- 入社日の未入力
- 教育項目名の未入力
- 習得目安の不正値
- 想定されていないカテゴリ
- 想定されていない習得状況
- 存在しないスタッフID
- 存在しない教育項目ID

画面側だけに任せず、
Java側でも入力値やIDを確認するようにしています。

---

## 7.7 DB接続情報を環境変数で管理

MySQLへ接続するための
ユーザー名とパスワードは、
ソースコードへ直接記述しないようにしています。

`application.properties`

```properties
spring.datasource.username=${DB_USERNAME}
spring.datasource.password=${DB_PASSWORD}
```

実際の値は、
開発PCの環境変数として設定します。

これにより、
GitHubへソースコードを公開した場合でも、
DB接続用のパスワードが直接公開されないようにしています。

# 9. 起動方法

## 9.1 MySQLデータベースを作成

MySQLで、
本システムで使用するデータベースを作成します。

```sql
CREATE DATABASE staff_management;
```

テーブルについては、
Spring Boot起動時にJPA / Hibernateによって作成・更新されます。

---

## 9.2 環境変数を設定

MySQLへ接続するため、
次の環境変数を設定します。

```text
DB_USERNAME
DB_PASSWORD
```

例：

```text
DB_USERNAME=root
DB_PASSWORD=MySQLで設定したパスワード
```

---

## 9.3 Spring Bootアプリケーションを起動

Eclipseなどの開発環境から、
Spring Bootアプリケーションを起動します。

---

## 9.4 ブラウザからアクセス

アプリケーション起動後、
ブラウザから以下へアクセスします。

```text
http://localhost:8080/staff
```

スタッフ一覧画面が表示されれば、
起動完了です。
